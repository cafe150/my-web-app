# システム仕様書：RelationMap（共通点・関係性可視化ツール）

## 1. システム概要

### 1.1 目的

入力された「自分」と「相手」の属性・性格・価値観・ライフスタイル情報を突き合わせ、共通点および相補関係（シナジー）をインタラクティブなネットワークグラフとして可視化する。相手への理解を深め、対話のきっかけを発見することを目的とする。

### 1.2 動作環境・アーキテクチャ

* **稼働形態**：ローカルスタンドアロン（`localhost` 実行）
* **バックエンド**：不要（外部DB・API通信なし）
* **推奨スタック**：
* フロントエンド：React (Vite) または Vanilla HTML/JS
* スタイリング：Tailwind CSS
* グラフ可視化エンジン：`vis-network`（物理演算・力学モデル採用）
* データ永続化：ブラウザ `localStorage`
* 辞書データ：静的ローカルファイル（`tags.json`）

## 2. 機能要件

### 2.1 ユーザー入力機能

* **2カラム入力UI**：
* 画面左：ユーザー自身（名前、選択済みタグ一覧、タグ入力欄）
* 画面右：対象者（名前、選択済みタグ一覧、タグ入力欄）


* **タグ追加・削除**：
* サジェスト候補クリックまたはEnter確定でタグ追加（チップUI表示）。
* タグチップ右端の「×」クリック、またはBackSpaceキーで削除可能。
* 辞書外の自由入力タグ（カスタムタグ）の追加も許容。



### 2.2 インクリメンタル・サジェスト機能

* **入力揺れ対応リアルタイム検索**：
* タグ入力欄への1文字入力ごとに、ローカルの `tags.json` を探索。
* タグ名（`name`）の部分一致に加え、平仮名・同義語リスト（`keywords`）の部分一致を判定。
* 最大5〜8件をドロップダウンに表示し、キーボード（上下キー・Enter）およびマウスで選択可能。


* **重複防止**：
* すでに対象カラムに追加済みのタグはサジェスト候補から除外。



### 2.3 グラフ可視化機能（マインドマップ・ネットワーク）

* **ノード（Node）定義**：
| ノード種別 | 形状/スタイル | 説明 |
| --- | --- | --- |
| **Person Node** | 大円（カラー：自分=ブルー、相手=パープル） | 自分および相手の名前を表示。 |
| **Common Tag Node** | 中円（カラー：ゴールド） | 両者が共通して所持しているタグ。両者の中央に配置。 |
| **Synergy Node/Edge** | 点線または特定カラー | 片方のタグと相手のタグが `pairs` 定義に合致する関係性。 |
| **Unique Tag Node** | 小円（カラー：グレー/淡色） | 自分のみ、または相手のみが持つ個別タグ。本人の周囲に配置。 |


* **エッジ（Edge / 線）定義**：
* **所属線**：Person Node から Unique Tag Node への実線（グレー）。
* **共通結合線**：自分 ── Common Tag Node ── 相手（太い実線 / ゴールド）。
* **シナジー線**：相補関係にあるタグ同士を結ぶ線（点線 / エメラルドグリーン）。


* **物理シミュレーション**：
* ドラッグ＆ドロップによるノード移動。
* バネ定数（Spring length）により、共通点が多いほど自分と相手のメインノード同士が中央へ引き寄せられる挙動を実装。



### 2.4 理解度促進・詳細表示機能

* **ノードクリックイベント**：
* グラフ上の Common Tag または Synergy エッジをクリックすると、下部またはモーダルに「**話題の切り口（対話ヒント）**」を表示。


* **シンクロ率スコア**：
* 共通点数およびシナジー数から算出した一致度スコア（%）をヘッダーにリアルタイム表示。

$$一致度(\%) = \frac{\text{共通タグ数} \times 2 + \text{シナジー組数}}{\text{総登録ユニークタグ数}} \times 100$$





### 2.5 状態保存・復元機能

* 入力された名前、選択タグ、およびグラフ表示状態をブラウザの `localStorage` に自動同期。
* ページ再読み込み時、直前の作業状態をそのまま復元。
* 「データをリセット」ボタンにより全消去を可能とする。

## 3. データ構造定義

### 3.1 タグ辞書マスタ（`tags.json`）

サジェストおよび関係性抽出に使用する静的マスターデータ。

```json
[
  {
    "id": "jealous",
    "name": "嫉妬深い",
    "category": "personality",
    "keywords": ["しっと", "独占欲", "やきもち", "ふあん", "重い"],
    "pairs": ["一途", "連絡マメ"]
  },
  {
    "id": "attentive",
    "name": "聞き上手",
    "category": "values_social",
    "keywords": ["ききじょうず", "傾聴", "おだやか", "相談役"],
    "pairs": ["話すのが好き", "自己主張が強い"]
  }
]

```

### 3.2 アプリケーション保持データ（`localStorage: relation_map_state`）

```json
{
  "user": {
    "name": "自分",
    "tags": ["嫉妬深い", "夜型", "ドライブ"]
  },
  "target": {
    "name": "相手",
    "tags": ["一途", "夜型", "カフェ巡り"]
  },
  "updatedAt": "2026-10-07T11:16:11.000Z"
}

```

## 4. 主要処理ロジック

### 4.1 サジェスト絞り込みアルゴリズム

1. ユーザー入力文字列 $Q$ を取得し、前後の空白を除去して小文字・平仮名に正規化。
2. 辞書内の全アイテムに対し、以下を判定：
* $Q$ が `name` に部分一致するか。
* $Q$ が `keywords` 配列内のいずれかの要素に部分一致するか。


3. 判定が真、かつ現在の対象者の登録済みタグリストに含まれない要素を抽出（最大8件）。

### 4.2 グラフ生成アルゴリズム

入力更新時、以下の手順でグラフ描画用オブジェクト `{ nodes: [], edges: [] }` を再構築する。

1. **ベースノード登録**：
* `UserNode`（ID: `user`）、`TargetNode`（ID: `target`）を作成。


2. **共通タグの抽出**：
* ユーザーのタグ配列と相手のタグ配列の論理積（積集合）を取得。
* 共通タグを `CommonNode` として登録。
* `user` → `CommonNode`、`target` → `CommonNode` の両方にエッジ（ゴールド）を張る。


3. **固有タグの登録**：
* 共通タグに含まれないタグを、それぞれの `UniqueNode` として登録。
* 所属するメインノード（`user` または `target`）との間にエッジ（薄グレー）を張る。


4. **シナジー（ペア関係）の走査**：
* ユーザー側固有タグと相手側固有タグの組み合わせを走査。
* 辞書マスターの `pairs` に互いのタグ名が含まれている場合、その固有ノード間にシナジーエッジ（グリーン点線）を張る。

## 6. 非機能要件・制約事項

* **完全ローカル動作**：外部通信（CDN含む）を極力排除し、オフライン環境でも動作可能なバンドル構成とする。
* **レスポンス性能**：サジェスト入力から候補描画までの遅延を 50ms 以内、ノード更新時の再計算を 100ms 以内に抑える。
* **保守性**：タグ辞書（`tags.json`）はコード本体から独立させ、JSONファイルを書き換えるだけでタグや関連性の追加・修正が反映される構造とする。
